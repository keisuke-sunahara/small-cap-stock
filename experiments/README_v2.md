## 2. 共通の条件

- **期間**：評価の予測日は 2018-09-28〜2025-07-31（83回）。総資産の推移は 2018-09-28 の引け〜2025-08-29 の引け（83か月）。ホールドアウト（2025-09-29 以降）は使わない
- **売買**：CLAUDE_v2_draft.md 第5章の基本の売買ルール（月次、売りは第1営業日の寄付、買いは第2営業日の寄付（2段目は第3営業日）、N=20、目標の金額 = 総資産 × 0.97 ÷ N、
  1株単位、バッファ上位20%、注文金額 ≤ 20日平均売買代金の1%）。資金50万円
- **コスト**：かぶミニは0%（主）と片道0.22%。100株の比較は一律0.3%と銘柄ごと
- **ウォークフォワード**：予測日ごとに学習し直す。学習の起点は予測日の23営業日前まで（22営業日の空白）、直近4年のローリング、2017-01-01以降
- **目的変数**：起点の2営業日後の始値 → 22営業日後の始値のリターンの、ユニバース内の順位（案A の係数の日（起点の3〜22営業日後）を含む行は使わない）
- **特徴量**：`all_v2`（v1 の16個 ＋ `ret_220_20d`・`dist_high_220d`）。日ごとにユニバース内の順位（0〜1）。欠損はリッジでは0.5、LightGBM ではそのまま
- **モデルの設定は固定**（`config/base.yaml` の `model.lightgbm`・`model.ridge`。v1 と同じ値）。結果を見てパラメータを調整しない
- **乱数**：LightGBM の seed 42、deterministic、スレッド4。目的変数の並べ替えは乱数シード42。ランダムのベースラインは乱数シード0〜999
- **ベースライン**：ランダム1,000回・モメンタム・リバーサル・ユニバース平均・TOPIX を買って持ち続けた場合。同じ期間・同じ売買ルール・同じコストで、フェーズ v2-1 で計算して `reports/` に保存したものを使う

## 3. 出す指標（`metrics.json` と `results.md`）

すべての実験で、次を同じ計算で出す（`src/compare.py` で並べて比べられるようにする）。

- Rank IC：月ごとの平均・標準偏差・t値（83か月）、年ごとの平均。月ごとの Rank IC を `logs/backtest/<実験ID>/rank_ic_monthly.csv` に保存
- 点数の上位20%（コストなし、等金額）の年率と、年率の超過リターン（基準B）。予測の5分位ごとの月の平均リターン
- かぶミニ（主）× コスト0%・0.22%：年率、年率の超過リターン、データ費用を引いた年率、TOPIX との差、シャープレシオ、最大ドローダウン、1か月の最大損失、税引き後の年ごとの成績、
  年ごと・前半・後半・相場環境ごとの超過リターン、約定率（1段目・2段目）、売れ残りの件数、現金の割合、回転、平均の保有月数
- ランダム1,000回の分布の中での位置（何パーセント点か。95%点との比較）、モメンタム・リバーサル・ユニバース平均・TOPIX との比較
- 合格基準 A〜G の各項目の判定（0%と0.22%の両方）
- 点数の上位20%（コストなし）の月ごとの超過リターンの平均・t値、年の超過リターンの平均（基準B）。N=20 の年率の超過と上位20%の年率の超過の差（7.4ポイントの決まり）
- 参考：今のかぶミニの取扱一覧（2026-10-05）に無い銘柄を飛ばして次の順位を買った成績（本番と同じ決まり）、100株の比較の成績（一律0.3%・銘柄ごと）、
  点数の上位20銘柄のうち、今の取扱一覧にある割合（基準 I の見込み）
- `metrics.json` に、データの取得日、gitのコミットID、実行日時、Market の作成日時、特徴量のハッシュ、試行回数（通算）を記録する

## 4. モデルの確定（EXP-101・102 の後）

1. EXP-103 で情報漏れが疑われないこと（EXP-103 の plan.md の基準）。疑われたら止めて報告する
2. 月ごとの Rank IC の差 d_m = （EXP-102 の Rank IC）−（EXP-101 の Rank IC）、m = 83か月。t値 = d の平均 ÷ d の標準偏差 × √83
3. **t値 ≥ 2 なら LightGBM（EXP-102）、それ以外はリッジ（EXP-101）**。ポートフォリオの成績（年率・超過リターンなど）では決めない
4. 確定したモデルが基準 A（Rank IC の平均がプラスで t値2以上）を満たさなければ、そのことを報告する（基準B の計算はする）

## 5. 基準B（モデルの確定の直後）

- 確定したモデルの、点数の上位20%（予測日ごとに等金額、コストなし、資金制約なし）について、月ごとの超過リターン（ユニバース平均（コストなし）との差、83か月）と、年の超過リターンの平均を計算する（定義は CLAUDE_v2_draft.md 第5章「目的変数と評価」）
- **次の両方を満たさなければ、EXP-104 と合格の判定に進まずに止めて報告する**（「優位性は見つからなかった」）
  1. 年の超過リターンの平均 ≥ データ費用の割合（19,800円 ÷ 50万円 = 3.96%）
  2. 月ごとの超過リターンが0より大きいことの t値（平均 ÷ 標準偏差 × √83）≥ 2
- 上回ったら、EXP-104 に進む。ここでは止まらない（結果は最後にまとめて報告する）

## 6. EXP-104 と合格の判定

- EXP-104（バッファなし）は参考で、採用候補にしない。確定したモデルの点数を使い、バッファだけを変える（毎月、上位20銘柄に入れ替える）
- 合格の判定は、**確定したモデル ＋ 基本の売買ルール（バッファあり）** で行う（CLAUDE_v2_draft.md 第9章の A〜G。H はホールドアウト（Rank IC と上位20%の超過）、I はペーパートレード（執行の確認）、J は試行回数）
- N=20 の年率の超過リターン（0%・0.22%）が、上位20%の年率の超過リターンを 7.4ポイント以上上回ったら、幸運か情報漏れを疑って調べ、見込みの値には上位20%の超過を使う（CLAUDE_v2_draft.md 第9章）
- 合格なら、`release-v2` の候補として提案し、ホールドアウトの前に止まる。不合格なら、結果をそのまま報告する

## 7. 試行回数の数え方

- 同じ検証期間（上の83か月）で成績を出した実験を1回と数える。v1 の4回（EXP-001・002・004・005）から通算
- 数えないもの：EXP-103（情報漏れの確認）、ベースラインの計算、E0
- 10回を超えたら止めて報告する
