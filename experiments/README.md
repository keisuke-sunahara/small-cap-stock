各実験の plan.md は、この文書の共通の決まりに従う。実験の一覧は `docs/EXPERIMENTS.md`。

## 1. 進め方と順番

1. **モデルの実験**（EXP-001〜005）：同じ特徴量（`all_v1`）・同じ売買ルール（基本ルール）で、モデルだけを変える
   - EXP-003（目的変数の並べ替え）は情報漏れの確認。**EXP-003 で情報漏れが疑われたら、そこで止めて報告する**
2. **モデルの確定**（第4章の手順）
3. **売買ルールの候補の実験**（EXP-006〜016）：確定したモデルの点数を使い、CLAUDE.md 第5章の候補を1つずつ変える（組み合わせの総当たりはしない）
4. 合格基準（CLAUDE.md 第9章）の判定と、`release-v1` の候補の提案、または「優位性は見つからなかった」の報告

各実験は `exp/EXP-xxx` のブランチで実行する。plan.md と config.yaml は、全実験の分をまとめて main で登録した（2026-10-05。一覧を一度に確認してもらうため。DECISIONS.md）。実行は `python -m src.run --exp EXP-xxx`。

## 2. 共通の条件

- **期間**：評価の予測日は 2018-09-28〜2025-09-19（364週。売買は 2018-10-01 の週から、ホールドアウトの前の週まで）。ホールドアウト（2025-09-29 以降）は使わない
- **ウォークフォワード**：評価の予測日を暦の月ごとにまとめ（85か月）、月ごとに学習し直す。学習の起点はその月の最初の予測日の6営業日前まで（5営業日の空白）、直近4年のローリング（EXP-005 を除く）。学習の開始は 2017-01-01 以降（CLAUDE.md 第5章）
- **点数を付ける日**：予測日と継続の判断の日（各週の最終営業日の前の営業日）の、ユニバースの全銘柄。日 d の点数には、「その月の最初の予測日 ≤ d」となる最も新しい月のモデルを使う（d の時点で学習を終えているモデルだけを使う）
- **特徴量**：`all_v1`（16個）。日ごとにユニバース内の順位（0〜1）に直す。欠損は LightGBM ではそのまま、線形モデルでは0.5で埋める
- **目的変数**：起点の翌営業日の始値から5営業日後の終値までのリターンの、ユニバース内の順位（CLAUDE.md 第5章。案A の係数の日を含む行は使わない）
- **乱数**：LightGBM の seed は `project.random_seed`（42）、`deterministic: true`、スレッド数4に固定。ランダムのベースラインは乱数シード0〜999
- **モデルの設定は固定**（`config/base.yaml` の `model`）。結果を見てパラメータを調整しない（調整したくなったら、別の実験として承認を取る）
- **ベースライン**：`reports/phase3r_baselines.json`（株式数の補正の後に計算し直したもの。同じ期間・同じ売買ルール・同じコスト）

## 3. 出す指標（`metrics.json` と `results.md`）

すべての実験で、次を同じ計算で出す（`src/compare.py` で並べて比べられるようにする）。

- **主の指標**：予算固定（毎週 30万円 ÷ N）・一律0.3%の、**年率の超過リターン**（戦略の年率 − ユニバース平均（コストなし）の年率）
- 予算固定と基本ルール（min(運用資金, 総資産) ÷ N）× コスト4通り（一律0.3%・一律0.5%・銘柄ごと（max(0.3%, 1呼値 ÷ 約定価格)）・なし）の、年率リターン・年率の超過リターン・シャープレシオ・最大ドローダウン・1週間の最大損失・税引き後の年ごとの成績
- 損益分岐の片道コスト（予算固定。年率の超過リターンが0になる一律のコスト）
- Rank IC：予測日の点数と翌週の実現リターン（最初の営業日の始値→最終営業日の終値）の、ユニバース内の順位相関。364週の平均・標準偏差・平均÷標準偏差・t値（週は重ならない）。年ごとの平均
- 予測の10分位ごとの翌週の平均リターン（ユニバース全体。コストなし）
- 約定率、現金のままだった週の割合、売買代金の回転（年あたり）
- 年ごと・相場環境（上昇・横ばい・下落）ごとの超過リターン
- 予測上位N（ユニバース内の点数の上位3）のうち、100株を買えない銘柄の割合
- 注文した銘柄のうち、予測日から30営業日以内に上場廃止になった割合
- ランダム（1,000回）の分布の中での位置（何パーセント点か）
- 合格基準（第5章）の各項目の判定
- `metrics.json` に、データの取得日、gitのコミットID、実行日時、Market の作成日時、特徴量のハッシュを記録する

## 4. モデルの確定（EXP-001・002・004・005 の後）

1. EXP-003 で情報漏れが疑われないこと（EXP-003 の plan.md の基準）。疑われたら止めて報告する
2. **採用候補**：次をすべて満たすモデル
   - Rank IC の平均がプラスで、t値が2以上
   - 予算固定の年率の超過リターンが、**一律0.3%と銘柄ごとのコストの両方で**、4つのベースライン（ランダムは1,000回の平均）をすべて上回る
3. 採用候補が複数あれば、予算固定・一律0.3%の年率の超過リターンが最も高いものに決める。ただし、**銘柄ごとのコストでも同じモデルが最も高いこと**（DECISIONS.md 2026-10-04 の比較のルール）。一致しない場合は、決めずに止めてユーザーに相談する
4. 採用候補が無ければ、売買ルールの候補には進まずに止め、結果と今後の選択肢を報告する（モデルが単純な方法に勝てない状態で売買ルールだけを調べても、合格にはならないため）

## 5. 売買ルールの候補の採用（EXP-006〜016）

- 比べる相手：確定したモデル ＋ 基本ルール（同じ点数）
- **採用の条件**（すべて満たす）：
  1. 予算固定の年率の超過リターンが、一律0.3%と銘柄ごとのコストの**両方で**基本ルールを上回る
  2. 予算固定・一律0.3%の週次リターンの差（候補 − 基本ルール）の t 値が 1.0 以上（364週。偶然の範囲の差で採用しないため）
  3. 予算固定・一律0.3%の最大ドローダウンが、基本ルールより5ポイント以上悪化しない
- 候補5（保有銘柄数 N）は参考として出すだけで、採用の判断はしない（N はユーザーの資金に合わせて決める）
- 候補6は、事前の確認（EXP-012 の plan.md）で傾向が無ければ実行しない（試行回数に数えない）
- 候補9は、開始週 H 通りの平均で判断する（最も良い・悪い開始週も併記する）
- **2つ以上の候補を採用する場合**：組み合わせた実験を1回だけ行い、各候補を単独で採用した場合を上回れば組み合わせを、そうでなければ単独で最も良い候補を採用する。組み合わせは第5章の「1項目ずつ」から外れるため、**その時点でユーザーの確認を取ってから行う**

## 6. 試行回数の数え方（CLAUDE.md 第8章）

- 同じ検証データ（上の364週）で成績を出した実験を、1回の試行として数える（モデルの実験、売買ルールの候補、組み合わせ）
- 数えないもの：EXP-003（情報漏れの確認で、選ぶ対象ではない）、事前の確認で実行しなかった候補6、ベースラインの計算
- この一覧のとおりに進めると、試行は最大15回（組み合わせを入れて16回）。20回を超えたら過学習の危険を警告し、30回を超えても合格基準に届かなければ止めて報告する
