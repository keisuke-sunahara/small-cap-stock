# v1 の結論

作成：2026-10-05／対象：main（タグ `v1-final`）／フェーズ4のモデルの確定（EXP-002）で研究を終えた

## 1. 結論

- **予測は効く。しかし、30万円・3銘柄・週次の売買では、売買コストとデータ費用を引くと利益が見込めない。**
- 確定したモデル（EXP-002 リッジ回帰）の Rank IC（予測の順位と翌週の実際の順位の相関）は 0.079（t値 9.1）で、どの年もプラスだった。
  一方、売買コストとデータ費用をすべて引いた年率は −9.7%〜−14.8% で、4通り（予算固定・基本ルール × 一律0.3%・銘柄ごとのコスト）すべてマイナスだった
- 評価役が点数から先を独立に計算し、計算の誤りは見つからなかった。評価役の判定は「止めるべき」。ユーザーの判断で v1 をここで終了した
- 売買ルールの候補（EXP-006〜016）は実行していない。**ホールドアウト（2025-09-29 以降）は取得も読み込みもしておらず、v2 のために残している**
- 合格基準は満たしていない。リリースは作っていない（`docs/RELEASES.md` は空のまま）

## 2. 根拠の数字

期間：予測日 2018-09-28〜2025-09-19（364週）。詳しくは `reports/phase4_model.md`。

| 予算 | コスト | 年率（売買コストを引いた後） | データ費用（年6.6%）も引いた年率 | 年率の超過（ユニバース平均との差） |
|---|---|---|---|---|
| 予算固定 | 一律0.3% | −7.88% | **−14.48%** | −5.98% |
| 予算固定 | 銘柄ごと | −8.22% | **−14.82%** | −6.31% |

- コストなしの年率は +6.65%（予算固定）。データ費用を引くとほぼ0、売買コストを引くと大きなマイナス
- 損益分岐の片道コスト（年率の超過が0になるコスト）は 0.17%。想定の0.3%より低い

- 試行回数は4（20回の警告の基準には遠い）

## 3. 分かったこと

### 3.1 利益が出ない理由
1. **売買コストが予測の効きより大きい。** 毎週ほぼ全部を入れ替えるため、売買代金の回転は年 約49倍。片道0.3%でも年 約14.6% を失う。
   ベースライン（ランダム選択）でも、コストなし −1.9% に対し、コスト0.3%で −18.9%（年率）
2. **資金に対してデータ費用が大きい。** 30万円に対して Light の年間費用は 6.6%（Standard なら 13.2%）。データ費用は資金に反比例するので、資金が小さいほど不利
3. **予測の上位を買えない。** 点数の上位3銘柄の 79.5% は100株を買えない（株価1,000円超）。実際に買うのは平均で8.6位の銘柄
4. **予測の効きは「下がる銘柄を避ける」側に偏っている。** 点数の最も低い10分位は週 −0.51% と大きく下がるが、上位の組の差は小さい（最上位の10分位で週 +0.15%）。
   買うだけの戦略（空売りなし）では、この効きを十分に使えない
5. **持っているだけでは増えない期間だった。** ユニバース平均（コストなし、月曜の寄付〜金曜の引け、配当なし）は年率 −1.9%

### 3.2 予測について
- 値動き・財務の16個の特徴量だけで、Rank IC は 0.08 前後、t値 9〜13 と安定してプラス。LightGBM と線形モデルの差は、週次リターンの差の t値で 1.5〜1.8（偶然の範囲を否定できない）
- 特徴量を1つずつ点数にした Rank IC は最大 0.068（値動きの大きさ、マイナス方向）。割安・時価総額・短期の反転など、よく知られた効果の範囲で、不自然に強い特徴量は無かった
- 目的変数を並べ替えると Rank IC は 0.002 になり、情報漏れは見つからなかった
- lambdarank（上位10%を当てる目的）は値動きの大きい銘柄を選ぶ性質があり、平均の Rank IC はマイナスになった（目的の選び方で結果が逆になる）
- 学習期間は、直近4年のローリングと拡大窓でほぼ同じ（差の t 0.23）
- 運用時の Light の範囲（5年分）の特徴量で学習しても、点数の順位相関は 0.9998 以上で、ほぼ同じになる

### 3.3 データと基盤について（v2 でそのまま使える）
- J-Quants のデータ（2016-10-05〜2025-09-26）は欠けなく取得でき、質は良好。上場廃止の759銘柄も含む
- 気を付ける点として分かったもの（すべて対応済み。`docs/DECISIONS.md`）
  - 2020-10-01 は終日の売買停止（カレンダー上は営業日）
  - API の調整後の列（AdjO など）と MktCap は後の分割の情報を含むので使わない
  - 調整係数が株価の動きと合わない例がある（±30% 超の判定で60営業日除外）
  - 決算短信の発行済株式数が、分割の前後で基準がずれる例がある（157件を補正）
  - 決算発表予定日の「未定」の記録を捨てると、予定日を誤って使う
  - 破綻型の上場廃止は、引け後〜翌朝の公表で、貸借信用区分「その他」に変わる前にユニバースにいることがある
- バックテスト基盤（指値の約定判定、呼値、100株単位と資金制約、ストップ高・安、継続保有、予算固定・基本ルール、銘柄ごとのコスト）は、評価役の独立の再実装と一致した
- 実験の事前登録・1コマンドの再実行（`python -m src.run --exp EXP-xxx`）・比較（`python -m src.compare`）の仕組みは動いている

### 3.4 運用の前提について（フェーズ0で確認）
- 楽天証券で寄付指値・引成・逆指値は使える。引成は11:30以降に入れないと前場引けで約定する。損切りは IFD で自動化できず、約定後に手動で入れる
- N=3（1銘柄10万円）で100株を買える銘柄は、ユニバース約1,000〜1,100銘柄のうち 約450〜470銘柄

## 5. 懸念点（v2 に向けて）

- **ホールドアウトは「見ていない」状態を保っている**が、v1 の結果（検証期間の成績）はすでに見ている。v2 で v1 の検証期間を使って設計を変えると、同じ検証データでの試行が重なる。
  v2 の試行回数は v1 の4回から数え始めるのが安全と考える
- v2 で資金・保有期間・目的変数などを変えて成績が良くなっても、それは v1 の結果を見た後の変更である。ホールドアウトでの確認がより重要になる
- データ費用は資金の大きさで決まるので、v2 で戦略を変えても、30万円のままでは年6.6%の不利は変わらない

## 6. v2 で検討できること（意見。決めたことではない）

- 売買の回数を減らす（保有期間を長くし、目的変数も保有期間に合わせる）
- 資金額ごとの損益分岐を計算する（第9章。データ費用を吸収できる資金の目安）
- 買える銘柄だけで学習・順位付けする（上位を買えない問題への対策）
- 「下がる銘柄を避ける」効きを使う方法（例：ユニバース全体から下位を除いて広く持つ）。ただし銘柄数が増えると100株単位の制約とぶつかる

いずれも v2 の開始時に、CLAUDE.md の目的・売買ルールの変更として、ユーザーの承認を取ってから進める。
