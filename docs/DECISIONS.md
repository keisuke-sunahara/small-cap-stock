### 2026-10-04 / フェーズ0の候補銘柄数の確認は、2025-06-30 以前の日付だけで行い、株価データは保存しない

### 2026-10-04 / J-Quants へのリクエストは上限の8割に抑え、429 を受けたら2分待つ
- 理由：公式の説明では、429 もカウントされ、待たずに再試行すると制限が延び、大幅超過で約5分遮断される。2分待ちは公式の推奨
- 他の選択肢：上限ちょうどで送る（遮断の危険）

### 2026-10-04 / 東証の営業日は、取引カレンダーの HolDiv が "1"（営業日）か "2"（半日立会）の日とする
- 理由：祝日は "3"（東証は休み、大阪取引所のみ祝日取引）で返ることを実データ（2025-03-20）で確認した。最初は "0" 以外を営業日としたため、祝日を含む期間で20営業日分の株価がそろわないと誤判定し、候補が0銘柄になる誤りが出た（修正済み・テスト追加）
- 他の選択肢：株価データがある日を営業日とみなす（売買停止の銘柄・データ欠損と区別できない）

### 2026-10-04 / ホールドアウトの開始日を 2025-09-29（月）に固定する
- 理由：2026-10-04 時点のデータの最終日は 2026-10-02（金）。その12か月前（2025-10-03）を含む週の月曜にそろえ、週次サイクルの途中で区切らないようにした（12か月と4日）。開発用の最後の週は 2025-09-22〜26（予測は 2025-09-19 の引け後）
- フェーズ5の時点ではデータがさらに増えるが、開始日は動かさない（ホールドアウトが12か月より長くなるだけ）
- 他の選択肢：2025-10-03（ちょうど12か月。週の途中で切れる）、2025-10-06（12か月に4日足りない）

### 2026-10-04 / データの取得はホールドアウト開始の前日（2025-09-28）までに限る
- 理由：「ホールドアウトのデータは読み込みも禁止」を確実に守るため、そもそも取得しない。フェーズ5の承認後に `--allow-holdout` で追加取得する（未取得分だけを取る作りのため、既存のファイルは変わらない）
- 決算発表予定日を銘柄コード指定で取ると期間を区切れずホールドアウト期間の記録まで返るため、コード指定は使わない（下調べで1回だけ実行し、公表日の範囲と件数だけを表示した。中身は見ておらず保存もしていない）
- 他の選択肢：全期間を取得して読み込み側で除外する（誤って読む危険が残る）

### 2026-10-04 / 取得の開始日は 2016-10-05 とする
- 理由：Standard で取れるのは「10年前」から（2026-10-04 時点で 2016-10-04〜。API の応答で確認）。取得が日付をまたいでも失敗しないよう、1日後ろにした
- 他の選択肢：2016-11-01 などきりのよい日（取れるデータを捨てることになる）

### 2026-10-04 / data/raw の保存形式：APIの応答をそのまま、1日1ファイル（期間で取るものは期間ごと）の Parquet
- 理由：再実行時に未取得の日だけを取れる。既存のファイルは上書きしない作りにして「data/raw は変更禁止」を守る。0件の日も空のファイルを残し、取り直さない。取得日時は `_fetch_log.csv` に記録する（metrics.json のデータ取得日に使う）
- 財務情報と決算発表予定日は、休日の開示・公表もあり得るため暦日すべてを取る（土日の例では0件だった）
- 他の選択肢：銘柄ごとのファイル（ホールドアウトを区切れない）、1つの大きなファイルへの追記（上書きが必要になる）

### 2026-10-04 / 普通株の判定は、商品区分 011（内国株券）＋ 市場区分（東証一部・二部・マザーズ・JASDAQ・プライム・スタンダード・グロース）＋ 銘柄コードの末尾が 0、を初期案とする（フェーズ1の品質チェックで確認）
- 理由：公式の注意書きで「内国株券には優先株式なども含まれ、商品区分だけでは普通株を抽出できない」とある。J-Quants の5桁コードは普通株が末尾0（優先株は末尾が0以外。例：25935）。ETF・REIT・優先出資証券は商品区分で除ける。TOKYO PRO MARKET（0105）と「その他」（0109）は除く
- 他の選択肢：業種コード「99（その他）」を除く方法（フェーズ0の概算で使った簡易版）

### 2026-10-04 / 学習用の目的変数は「翌営業日の始値から5営業日後の終値まで」のリターンの順位とする（初期案。フェーズ2で確定）
- 理由：実際の売買は寄付で買い、週の最終営業日の引けで売るため、終値起点より実際の損益に近い
- 他の選択肢：終値から5営業日後の終値まで（一般的だが、予測直後の寄付の窓を含んでしまう）
