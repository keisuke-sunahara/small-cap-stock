## 1. データ（J-Quants API V2）

2025年12月22日以降の新規登録は V2 API のみ。認証はダッシュボードで発行する API キーを `x-api-key` ヘッダーで送る方式。ベース URL は `https://api.jquants.com/v2/`。

### 1.1 使うデータ

| データ | エンドポイント | Light | Standard | 更新時刻（公式） | 用途 |
|---|---|---|---|---|---|
| 上場銘柄一覧（日付指定で当時の一覧） | `/equities/master` | ○ 5年 | ○ 10年 | 17:30頃（翌営業日分）／8:00頃 | ユニバース、上場廃止銘柄を含める |
| 株価四本値（調整前・調整後、ストップ高安フラグ、売買代金） | `/equities/bars/daily` | ○ | ○ | 16:30頃 | 特徴量・目的変数・約定判定 |
| 財務情報（決算短信。開示日・開示時刻、発行済株式数、会社予想） | `/fins/summary` | ○ | ○ | 18:00頃（速報）・24:30頃（確報） | 時価総額、財務特徴量、上振れ・下振れ |
| 決算発表予定日（**公表日つき・変更履歴あり**） | `/fins/earnings-date` | ○ | ○ | 10:05頃 | 「決算の回避」ルール、決算までの日数 |
| TOPIX 四本値 | `/indices/bars/daily/topix` | ○ | ○ | 16:30頃 | 地合いフィルター、相場環境の分類 |
| 取引カレンダー | `/markets/calendar` | ○ | ○ | 毎年3月末頃に翌年分 | 東証の営業日 |
| バリュエーション指標（参考） | `/equities/valuation` | ○ | ○ | 16:30頃 | 検算用（時価総額は自己株式控除後の定義なので本番の計算には使わない） |

- 決算発表予定日は `/fins/earnings-date` に「公表日（PubDate）」と変更履歴が残るため、**各時点で知り得た予定日だけを使える**（未来情報を避けられる）。
- 株価は分割・併合・ライツイシューの調整係数（AdjFactor）つき。現金配当は調整されない。
- 売買不成立の日は四本値・出来高が Null。ストップ高・ストップ安フラグ（UL/LL）あり。
- 上場銘柄一覧は日付を指定すると当時の上場銘柄が返る（上場廃止銘柄を含められる）。**過去の売買単位は提供されない** → 売買のバックテストは売買単位が100株に統一された **2018-10-01 以降** に限定する（DECISIONS.md）。

### 1.2 プランごとの制約

| プラン | 月額 | 取得できる期間 | 遅延 | レート制限 |
|---|---|---|---|---|
| Free | 0円 | 12週前〜2年12週前 | **12週** | 5件/分 |
| Light | 1,650円 | 5年前まで | なし | 60件/分 |
| Standard | 3,300円 | 10年前まで | なし | 120件/分 |
| Premium | 16,500円 | 20年前まで | なし | 500件/分 |

- 財務情報・財務諸表のエンドポイントは、プランにかかわらず個別に **60件/分**。
- 制限超過は HTTP 429。待たずに再試行すると制限時間が延びる。大幅な超過で約5分遮断。→ クライアントは上限の8割に抑え、429 では2分待つ（`src/data/jquants.py`）。
- Free は12週遅れのため週次運用には使えない。

### 1.3 取得量の見積もり（Standard）

日付指定で全銘柄を取ると、約2,400営業日 ×（株価・銘柄一覧・財務・決算予定）でおよそ1万リクエスト。財務情報は60件/分の制限のため、全体で数時間。初回だけで、以後は差分のみ取得する。

## 2. データ費用の費用対効果と利用規約（ユーザーからの依頼事項）

### 2.1 結論
- **運用資金30万円に対して、データ費用は無視できない大きさ**。Standard は年39,600円＝資金の **13.2%/年**、Light でも年19,800円＝ **6.6%/年**。売買コストとは別に、この分を毎年上回れなければ、データ代を払って運用する意味がない。
- 推奨：**研究（フェーズ1〜5）は Standard で短期間（目安1.5〜2か月）に集中して行い、運用（フェーズ6〜7）は Light で行う**。そのために、**特徴量は Light で取れるデータだけで作る**（Standard 限定の信用残・空売り・EDINET 等は使わない）。
- ただし **Standard → Light に下げたときに、5年より古いデータを消す必要があるかは、利用規約からは判断できない**。J-Quants への問い合わせをお願いしたい（第2.3節）。

### 2.2 費用の見込み

| 期間 | プラン | 費用 |
|---|---|---|
| フェーズ1〜5（研究・最終評価） | Standard × 2か月 | 6,600円 |
| フェーズ6（ペーパートレード 12週以上） | Light × 3か月 | 4,950円 |
| フェーズ7（実運用、年間） | Light × 12か月 | 19,800円 |

- 年間のデータ費用が資金の1%以下になる運用資金は、Light で約200万円、Standard で約400万円。資金30万円のままでは、**データ費用控除後に「ユニバース平均を上回る」ためには、年率6.6%以上の超過リターンが必要**になる。これは小型株の週次戦略としてかなり高いハードルである。
- このため、評価では「データ費用（運用時のプランの年額 ÷ 運用資金）を差し引いた成績」も併記する。合格基準への追加も提案する（第9章）。

### 2.3 利用規約の確認結果（J-Quants API サービス利用規約・FAQ）
- **解約後に取得済みデータは使えない。** 第7条「サブスクリプションをキャンセルし現在の残りの請求対象期間が終了した後、ただちに本データ及びその複製物を全て廃棄若しくは消去」。退会時も同様（第15条第5項）。FAQ では、元データを復元できる派生物も削除が必要、**復元できない派生物（分析結果など）は外部に配信しなければ削除不要**。
- **プラン変更（ダウングレード）時の扱いは記載がない。** Standard で取った「5年より古いデータ」を Light 移行後も保持できるかは不明。→ **ユーザーから J-Quants の問い合わせ窓口に確認をお願いしたい**（私は代わりに問い合わせを送れません）。回答が得られるまでは、保守的に「移行時に5年より古いデータは削除が必要」と仮定して計画する。その場合、評価役によるフェーズ2〜5の独立検証は、Standard の契約中に終える必要がある。
- **利用は登録ユーザー本人の私的使用に限る**（第8条）。第三者が使用できる状態にすること、商用・学術目的は不可。本人だけが見られる外部クラウドへの保存は可（FAQ）。
  - `data/` はコミットしない（既に `.gitignore` に入れた）。
  - `logs/backtest/` にコミットする予測スコアには、**株価そのものを含めない**（銘柄コード・日付・スコア・順位のみ）。
  - 評価役は同じPCの `evaluator/` で、ユーザーご本人が起動・管理し、データを外部に共有しない（2026-10-04 ユーザー回答）。私的使用の範囲内と判断する。

## 3. 証券会社（楽天証券）で必要な注文が使えるか

| 必要な注文 | 楽天証券 | 注意点 |
|---|---|---|
| 寄付の指値（買い） | **○** 指値＋執行条件「寄付」 | 前場の寄付前に入力すると前場の寄付で執行。寄付で約定しなければ失効（基本ルールと一致）。前日夜・週末に入力しておける |
| 引成（売り） | **○** 成行＋執行条件「引け」 | **前場終了（11:30）前に入力すると「前場引け」で執行され、大引けには繰り越されない。** 大引けで売るには、**11:30 以降（目安は12:30〜15:00）に入力する必要がある** |
| 逆指値（損切り） | **○** 逆指値注文。執行条件「今週中」「期間指定」可 | 発動すると「本日中」に変わる。**権利付最終売買日・決算の権利付最終売買日をまたぐと繰り越されず失効**するため、入れ直しが必要 |
| IFD（買い→自動で損切り） | △ セット注文はあるが、**売り側に逆指値は使えない** | 損切りは買いの約定後に手動で逆指値を入れる（第6章の流れどおり） |
| 手数料 | ゼロコース（SOR の利用同意が条件）で国内株式の手数料0円 | 片道0.3%はすべてスリッページ・板の薄さの見込みとして使う |

- 注意：最初の質問で「売りの引成は朝のうちに入れておける」と書いたが、**楽天証券では朝に入れると前場引けで約定してしまうため誤りでした。** 注文リストに「引成は11:30以降に入れる」と明記する。
- ご回答の時間帯（朝9:00前・日中）なら、買いは前日夜〜朝、売りは昼休み〜後場に入れられるので、運用は可能。
- 未確認：寄付・引け条件の注文に SOR が適用されるか（取引所の寄付・引けで約定するなら影響は小さい）。フェーズ6の前に確認する。

## 4. 運用資金30万円・N=3 で候補になる銘柄数

### 4.1 結果（J-Quants Free プランの実データ、2026-10-04 実行。`reports/phase0_candidates.json`）

| 日付 | ユニバース | N=2（予算15万円・株価1,500円以下） | **N=3（予算10万円・株価1,000円以下）** | N=5（予算6万円・株価600円以下） | ユニバースの株価の中央値 |
|---|---|---|---|---|---|
| 2024-09-30 | 1,067 | 669 | **461** | 252 | 1,165円 |
| 2024-12-27 | 1,021 | 664 | **449** | 264 | 1,103円 |
| 2025-03-31 | 1,109 | 694 | **465** | 286 | 1,170円 |
| 2025-06-30 | 1,043 | 665 | **469** | 284 | 1,116円 |

- **N=3 なら、ユニバースの約43%（約450〜470銘柄）が100株単位で買える。** 上位3銘柄を選ぶ母集団としては十分な数で、**N=3 は妥当**と考える
- N=5 でも250〜290銘柄残るが、予算6万円で株価600円以下に限られる。N=2 は候補が多いが、1銘柄の値動きの影響がさらに大きくなる
- 売買代金の上限（1%）は、ユニバースの条件（平均売買代金3,000万円以上 → 1%は30万円）が予算10万円より大きいため、**30万円の資金では効かない**ことを確認した

### 4.2 提案
- **N の初期値は3のままとする。** N=2・3・5 の比較は CLAUDE.md の「比較する売買ルールの候補5」として、参考として出す
- 注意：株価1,000円以下という制約で、ユニバースの半分以上（主に株価の高い銘柄）が買えない。モデルの予測上位が買えない銘柄に偏ると、実際に買うのは順位の低い銘柄になる。バックテストではこの制約を正確に再現する（買えない銘柄は飛ばして次の順位へ）。そのうえで、フェーズ4で「予測上位のうち買えない銘柄の割合」を報告する

### 4.3 この概算の限界（フェーズ1・2で正式な定義に置き換える）
- 時価総額は J-Quants のバリュエーション指標の値（自己株式を除いた株式数で計算）を使った。CLAUDE.md の定義（開示済みの発行済株式数で計算）より少し小さくなるため、ユニバースがわずかに大きめに出ている可能性がある
- 普通株の判定は、市場区分（プライム・スタンダード・グロース）と業種コード「99（その他）」を除く簡易的な方法で行った。商品区分（ProdCat）の値の意味はフェーズ1で確認する
- 株数の計算は、指値ではなく終値で行った

### 4.4 確認の方法（記録）
- 1銘柄の予算は 30万円 ÷ 3 = 10万円 → 100株買うには **株価1,000円以下** が必要（N=2 なら1,500円以下、N=5 なら600円以下）。
- 売買代金の上限（注文金額 ≤ 過去20営業日平均売買代金の1%）は、注文10万円なら平均売買代金1,000万円以上で満たす。ユニバースの条件（3,000万円以上）の方が厳しいため、**この上限は30万円の資金ではほぼ効かない**。
- 確認方法：`python -m src.analysis.phase0_candidates`。ホールドアウトに触れないよう、**2025-06-30 以前の4日（2024-09-30、2024-12-27、2025-03-31、2025-06-30）だけ**を使い、取得した株価は保存せず銘柄数だけを出力する。
- J-Quants の Free プラン（無料。2年分・12週遅れ）でこの期間は取得できるため、**Standard の契約前に費用ゼロで確認できる**。

## 7. 売買ルールとバックテスト（フェーズ2）

CLAUDE.md 第5章の基本ルールを再現する。

- 予測：週の最終営業日の引け後
- 買い：翌週の最初の営業日の寄付、指値 = 前営業日終値 × 1.02 を呼値の単位で切り下げ。**始値 ≥ 指値なら買えなかった**、寄らなかった場合も買えなかった
- 売り：その週の最終営業日の大引け（引成）。売れなかった場合は次に売買が成立した日の始値
- 継続保有：翌週も上位N銘柄に入った保有銘柄は売らない
- 株数：予算 = 運用資金 ÷ N の範囲で100株単位の最大株数。100株も買えない銘柄・注文金額が平均売買代金の1%を超える銘柄は除外し、次の順位へ
- コスト：片道0.3%（0.5%も併記）
- 呼値の単位：東証の通常の呼値（TOPIX100 構成銘柄向けの細かい呼値は、小型株のユニバースでは基本的に該当しないが、該当銘柄があれば当時の表を使う）
- ストップ高・ストップ安：株価四本値の UL/LL フラグと、始値が Null（売買不成立）かで判定
- 比較する売買ルールの候補（7つ）は CLAUDE.md 第5章のとおり、1つずつ変えて比較する

### 7.1 ルールの細部で確認したい点（フェーズ2までに決める）
1. **営業日が1日しかない週**（年末年始・連休など）：その日の寄付で買って同じ日の引けで売ることになる。そのまま適用するか、その週は休むか（初期案：そのまま適用）
2. **予算の基準**：「運用資金」を固定の30万円とするか、その時点の総資産（利益を再投資）とするか（初期案：`min(30万円, 現在の総資産) ÷ N`。損失時は買える額が減り、利益は再投資しない）
3. **継続保有中にユニバースから外れた銘柄**（時価総額500億円超え等）：上位N銘柄に「選ばれなかった」ものとして売る（初期案）
4. **保有中の上場廃止**：整理銘柄としての最終売買日の終値で売れたものとする（初期案）

## 8. 検証方法

- ウォークフォワード：毎月再学習し、翌1か月を評価。学習期間の終わりと評価期間の始まりの間に5営業日以上の空白
- 期間の見込み（Standard 契約時点から10年＝2016年11月頃〜）
  - 特徴量の計算に60営業日 → 2017年2月頃から
  - 最初の学習に約2年 → **評価は2019年1月頃〜ホールドアウト開始の前まで（約6.8年・約350週）**
  - ホールドアウト：直近12か月。開始日はフェーズ1でデータの最終日から決めて `config/base.yaml` に固定（2025年10〜11月頃になる見込み）
- ベースライン4つ（ランダム、モメンタム、リバーサル、ユニバース等金額平均）を同じ売買ルール・資金制約で計算
- 目的変数をランダムに並べ替えた学習で、成績がほぼゼロになることを確認
- 同じ検証データでの試行回数を数え、20回を超えたら警告

## 9. 合格基準の見直し案（CLAUDE.md 第9章。承認が必要）

現行の基準は維持したうえで、次の追加・明確化を提案する。

1. **データ費用控除後の成績を追加**：「運用時のプランの年間データ費用 ÷ 運用資金（30万円・Light なら6.6%/年）を差し引いた年率リターンが、ユニバース全体の等金額平均を上回る」
   - 理由：これを満たさないなら、データ代を払わずに小型株の指数連動の投資信託などを持つ方が合理的なため
   - リスク：資金30万円では厳しい基準で、満たせない可能性が高い。その場合は「資金を増やせば成り立つか」を、資金額ごとの損益分岐として報告する
2. **ランダム選択のベースラインは乱数シードを変えて1,000回計算し、その平均を上回ること**とし、分布の中で何パーセント点にあたるかも併記する
   - 理由：1回のランダム選択は運の影響が大きく、比較の基準として不安定なため
3. **Rank IC の t 値は、週次（重ならない期間）の IC から計算する**ことを明記する
   - 理由：日次起点の5日リターンの IC は期間が重なり、t 値が実力以上に大きく出るため

## 10. CLAUDE.md の改善提案（承認が必要。CLAUDE.md 自体は変更していない）

1. **第6章の売りの時刻**：「その週の最終営業日 15:30まで … 引成で売り注文を入れる」→ 楽天証券では「**11:30（前場終了）以降、15:00頃までに**引成を入れる（前場中に入れると前場引けで約定するため）」に変更

   - なぜ改善になるか：金曜引け後の決算は月曜の寄付に大きく反映されるため、使えれば予測が改善する可能性がある
   - リスク：バックテストで「反映時刻」を正確に再現できないと、未来情報が混ざる。J-Quants の財務情報の反映は18:00頃・24:30頃（最大1時間程度の遅延あり）なので、**開示時刻が金曜の当日中のものに限る**などの保守的な線引きが必要。成績が実力以上に良く見える危険があるため、採用する場合は、現行ルールと両方の成績を出す
   - 初期案は「現行ルールのまま」。変える場合のみ承認をお願いしたい
4. **第9章**：上記第9章の3点
5. **第7章 フェーズ0**：「候補銘柄数の確認は、ホールドアウトに入らない過去の日付で行う」を明記（今回はそのように実施する）

## 12. 懸念点

1. **データ費用**：第2章のとおり、資金30万円ではデータ費用が年6.6〜13.2%に相当し、最大の障害になりうる
2. **少額・少数銘柄による成績のばらつき**：N=3 では1銘柄の値動きの影響が大きく、12週のペーパートレードでは実力と運を見分けにくい
3. **検証期間の短さと過学習**：評価に使える期間は約350週。試行を重ねるほど偶然良く見える結果を選ぶ危険がある（試行回数を記録し、20回超で警告）
4. **小型株のスリッページ**：寄付・引けの板が薄い銘柄では片道0.3%を超えることがある。0.5%の場合も併記し、ペーパートレードで実際のずれを確認する
5. **楽天証券の注文の使い方の誤り**：引成を前場中に入れると前場引けで約定する。注文リストに明記する
6. **プラン変更時のデータの扱い**：J-Quants の回答次第で、評価役の検証やバックテストの再現の段取りが変わる
7. **評価役とデータの共有**：評価役はユーザー本人が同じPCで管理するため問題なし（2026-10-04 確認）。評価役が別の人に変わる場合は、J-Quants のデータを渡せない
8. **Python 3.14**：新しい版のため、一部ライブラリの対応が遅れる可能性。現時点で必要なライブラリ（LightGBM 4.7 等）は動作を確認済み
